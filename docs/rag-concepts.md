# RAG 检索编排：概念笔记

记录对"检索编排"这一核心概念的理解过程，用于面试前复习。

## 要解决的问题

用户问一个关于私有文档的问题（比如"DocMind 用什么向量数据库？"），如果直接把这句话丢给大模型，模型只能凭训练时见过的通用知识回答——它根本不认识"DocMind"这个项目，无法回答任何具体细节。

RAG（Retrieval-Augmented Generation，检索增强生成）要做的事，就是在问模型之前，先从自己的文档里找到相关内容，把这些内容一起交给模型，让模型"照着资料来回答"。

"检索编排"指的就是组织"先找资料、再拼给模型、最后生成回答"这整个流程。

## 三个动作

### 1. 检索（Retrieval）——找资料

**前提准备**（入库阶段完成）：
- 把文档切成小段（几百字一块），避免整篇文档塞给模型（塞不下，且大部分内容和当次问题无关）
- 用 embedding 模型把每一小段转换成向量（一串数字，代表这段文字的语义）
- 把"文字片段 + 向量"存进向量库（FAISS）

**检索发生时**：
1. 把用户问题也转换成向量（用同一个 embedding 模型）
2. 拿问题向量去向量库里找"向量最接近"的几个片段（向量接近 = 语义相近）
3. 返回这几个最相关的原文片段，以及它们来自哪个文档、第几段

**代码对应**：
```python
docs = retriever.invoke(question)
```
这一行触发真正的检索动作，`docs` 是产出——几段和问题最相关的原文（`Document` 对象列表）。

### 2. 拼装（Prompt 拼接）——把资料和规则一起交给模型

拿到检索结果后，不能直接把"资料 + 问题"随意拼在一起，而是要通过一个模板，明确告诉模型该怎么用这些资料。

**为什么要明确约束模型**：如果不加规则，模型可能依然习惯性地用自己训练时的通用知识回答，甚至编造资料里没有的内容（"幻觉"）。约束的作用是让回答尽量忠于文档内容。

**代码对应**：
```python
def format_docs(docs) -> str:
    return "\n\n".join(f"[{i + 1}] {d.page_content}" for i, d in enumerate(docs))
```
把原文加上编号拼成字符串，编号是为了让模型能够引用（"如 [1]、[2]"），也让最终展示的"引用来源"和正文标注对得上。

提示词模板明确写了规则：
- 只使用资料中的信息
- 引用时标注编号
- 资料没有答案时，直接说"资料未提供相关信息"

### 3. 生成（Generation）——模型基于拼好的内容作答

把"规则 + 资料 + 问题"拼好的完整文本发给大模型，模型生成回答。这一步本身就是普通的"问模型、模型答"，区别在于这次模型看到的问题里夹带了专门准备的参考资料。

**代码对应**：
```python
answer_chain = prompt | llm | StrOutputParser()

for token in answer_chain.stream({"context": context, "question": question}):
    yield ("token", {"text": token})
```
`{context, question}` 套进模板生成完整文本 → 发给模型 → 模型逐字生成 → 通过 `yield` 把每个字往外抛（最终变成 SSE 的 token 事件推给前端）。

## 三步对照表

| 步骤 | 代码位置 | 输入 | 输出 |
|---|---|---|---|
| 检索 | `retriever.invoke(question)` | 用户问题（字符串） | 相关原文片段（Document 列表） |
| 拼装 | `format_docs(docs)` + prompt 模板 | 上一步的原文列表 | 拼好的完整文本（资料+规则+问题） |
| 生成 | `answer_chain.stream(...)` | 拼装好的完整文本 | 模型逐字生成的回答 |

## 自查问题与理解验证

**Q：为什么不能把整篇文档直接丢给大模型，非要先做检索？**
A：一是文档可能超出模型能处理的长度；二是大部分内容和当次问题无关，直接塞进去是浪费，还会干扰模型聚焦到真正相关的部分。

**Q：如果把检索结果设为空字符串（不检索），会发生什么？**
A：模型会按提示词里的规则，回答"资料未提供相关信息"——这是规则生效的结果，不是模型自己"知道"没有资料该怎么办。

**Q：如果提示词里删掉"没有答案时如何应对"这条规则，会发生什么？**
A：模型会退回到用自己训练时的通用知识回答，即产生"幻觉"——看起来像是根据资料回答的，实际上是编造的。这说明大模型本身不会主动判断"我没有依据"，需要在 prompt 里明确"教"它遇到这种情况该怎么处理。

**Q：如果检索到的内容和问题实际上不相关（比如知识库里根本没有相关内容，但向量检索依然会返回"相似度最高的几个"，即便相似度本身也不高），会发生什么？**
A：模型可能会"矬子里拔将军"，硬把这些不太相关的片段拼凑成一个看起来逻辑通顺、实际上文不对题的回答。这是 RAG 系统一个真实存在的局限性。

## 局限性与优化方向（进阶知识，面试可提及）

1. **重排序（Reranking）**：检索先粗召回较多候选（比如 20 个），再用专门的重排序模型对"问题-片段"的真实相关度重新打分，只保留最相关的几个，减少"凑数"导致的幻觉。属于进阶优化，本项目暂未实现。

2. **相似度阈值过滤**：给检索结果设一个最低相似度门槛，如果最高分都达不到阈值，直接判定为"知识库中无相关内容"，跳过生成步骤，直接返回"资料未提供"，不让模型看到勉强凑数的片段。成本低，是比较容易加的优化点。

## 一句话总结

检索编排不是发明新算法，而是把"检索（找资料）→ 拼装（按模板+规则组织内容）→ 生成（模型作答）"这三个现成能力，按正确的顺序和方式串联起来。核心价值在于：通过检索让模型"看到"私有知识，通过 prompt 规则约束模型"忠于资料"而不是自由发挥。
